# Network Scan Detection — CSI 4460/5460

This website uses **fixed filenames** so the proposal and first report can be replaced without editing HTML again.

## Important filenames and locations

At the repository root:
- `index.html`
- `proposal.html` (links to `docs/proposal.pdf` and `docs/proposal.docx`)
- `report1.html` (links to `docs/report1.pdf` and `docs/report1.docx`)
- `styles.css`

Inside `docs/`:
- `proposal.pdf` and `proposal.docx`
- `report1.pdf` and `report1.docx`

## First-time website update

1. Unzip this archive on your computer.
2. Open your **existing** GitHub repository; do not create a separate one.
3. Upload or overwrite `proposal.html` and `report1.html` at the repo ROOT, next to `index.html`.
4. Open the `docs` folder in GitHub and upload/overwrite all four documents with the EXACT filenames above.
5. Commit the changes. The GitHub Pages site will update after it builds and publishes.
6. Visit the Proposal and Report 1 tabs. Test PDF preview, Open PDF, and Download Word.

## Later document updates

Only replace the corresponding `.pdf` and `.docx` in the repository's `docs/` folder, preserving filenames exactly. The HTML does not need to change.

If GitHub adds a suffix like `(1)` to a local filename, rename it back *before uploading*. GitHub Pages paths are case-sensitive. Browser caching can briefly show the old document after commit; refresh or use a private window.

**Important:** Upload the files from the unzipped folder, not the .zip itself. A ZIP uploaded as one file to GitHub will not replace the site pages.

The `proposal.*` files supplied in this package are the original project-proposal-draft documents, only renamed. Replace them with your newer proposal if you have revised it.
