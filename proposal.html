Project proposal

Detecting Network Scanning Activity Using Nmap and Wireshark

Alexandro SeguraCSI 4460/5460 · Fall 2026

ON THIS PAGE

ProblemResearch questionApproachChallengesMilestonesResources

1. Problem statement

Network scanning is commonly used to discover available devices, open ports, and network services. It can be a useful tool for administrators, but attackers can also use it to collect information before attempting to exploit a system. Detecting this activity can help network defenders recognize suspicious behavior earlier.

This project will study how common Nmap scans appear in packet captures and whether straightforward traffic indicators can distinguish scans from normal connections.

2. Research question

How can Wireshark packet captures be used to identify TCP connect scans and SYN scans generated by Nmap, and what are the limitations of using simple detection rules?

3. Proposed approach

The project will use an isolated test environment with an authorized scanning machine and target. Wireshark will capture traffic while the machines generate both ordinary connections and controlled scans.

  1. Set up the lab and verify traffic can be captured reliably.
  2. Capture baseline network activity that is not intentionally generated by scanning.
  3. Run Nmap TCP connect scans and SYN scans against the lab target.
  4. Examine TCP flags, connection outcomes, destination ports, packet rates, and timing patterns.
  5. Propose simple detection indicators, compare them with the baseline, and evaluate false positives and missed detections.

The final paper will discuss the results and the conditions under which these indicators are useful or misleading.

4. Research challenges

Normal software may contact multiple ports or generate bursts of traffic, so a rule based only on the number of connections could produce false positives. Scan characteristics may also change depending on which ports are open or closed and how the scan is configured. Testing in a small lab will limit how broadly the findings can be generalized.

5. Milestones

  • October 31: First progress report covering background research, experiment design, and current progress.
  • November 14: Second progress report covering lab setup, captures, or preliminary analysis as available.
  • December 12: Present research process, findings, and limitations.
  • December 13: Submit the final research paper by 1:00 PM.

6. Resources

Planned tools include Nmap for network scans, Wireshark for packet captures, and virtual machines or another isolated network environment for authorized testing. No special instructor-provided resources are currently anticipated.
